# Reklama.uz — Frontend Technical Architecture

Brief reference for the `frontend/` app. For product framing see the README; this doc is about how the code is put together.

## What it is

Reklama.uz is a marketplace for booking creator advertising (Instagram/Telegram/TikTok/YouTube) in Uzbekistan — think Collabstr. Businesses discover creators, compare packages, check availability, and book; creators list packages and get booked. Currently a **frontend-only prototype**: all data in `src/lib/data.ts` is static/mock, there is no backend, auth, or payment integration yet.

## Stack

| Layer | Choice |
|---|---|
| Framework | TanStack Start (React 19, SSR) |
| Routing | TanStack Router, file-based (`src/routes/`) |
| Styling | Tailwind CSS v4 + a small custom design system (`src/styles.css`) |
| Components | shadcn/radix primitives in `src/components/ui/` |
| Data fetching | `@tanstack/react-query` (`QueryClient` wired in `src/router.tsx`, not yet used for real fetches) |
| Package manager | bun (`bun.lock`, `bunfig.toml`) |
| Build | Vite 8 + `@tanstack/router-plugin` (regenerates `src/routeTree.gen.ts` — never hand-edit it) |
| Scaffold | Generated by [Lovable](https://lovable.dev); see `frontend/AGENTS.md` for its git-history caveat |

### Commands (run from `frontend/`)

```sh
bun install
bun run dev       # vite dev, picks a free port starting at 8080
bun run build     # production build
bun run lint      # eslint (prettier rules included)
bun run format    # prettier --write
```

## Routing

Convention: `src/routes/foo.tsx` → `/foo`, `src/routes/foo.$bar.tsx` → `/foo/:bar` (see `src/routes/README.md`). `__root.tsx` is the app shell (head tags, error/not-found boundaries, `<Outlet/>`).

| Route file | URL | Status |
|---|---|---|
| `index.tsx` | `/` | Landing page |
| `discover.tsx` | `/discover` | Browse/filter creators |
| `matches.tsx` | `/matches` | AI-ranked creator matches |
| `copilot.tsx` | `/copilot` | Campaign-brief input form |
| `creator.$username.tsx` | `/creator/:username` | Creator profile + booking |
| `how-it-works.tsx` | `/how-it-works` | Marketing/FAQ page |

**Linked but not built yet:** `/dashboard`, `/studio`, `/auth` are referenced from `SiteNav`/`SiteFooter`/CTAs and will fail `tsc` (`Type '"/dashboard"' is not assignable...`) until those route files exist. This is expected in the current state, not a regression — `dash-shell.tsx` looks like the intended shell for `/dashboard` and `/studio`.

## Design system (`src/styles.css`)

- Tailwind v4 via `@theme inline`; all colors defined as CSS custom properties in oklch (`--background`, `--primary`, `--surface`, `--warning`, etc.) and mapped to `--color-*` utilities. Dark mode variant exists (`.dark`) but isn't toggled anywhere yet.
- Two font families: `--font-sans` (Inter, body) and `--font-display` (Plus Jakarta Sans, all headings).
- Custom radius scale (`--radius-sm` … `--radius-4xl`) and two shadow utilities, `shadow-soft` / `shadow-lift`, used instead of Tailwind's defaults for cards.
- `.ai-chip` utility: the pill used for anything AI-related (Copilot, match badges).
- Convention throughout: `rounded-2xl`/`rounded-3xl` cards, `border border-border bg-card`, `font-display` for headings. New UI should match this rather than introduce new patterns.

## Data model (`src/lib/data.ts`)

- `Creator`: profile + stats (followers, engagement, rating), `audience` breakdown, `services: Service[]`, and `unavailableDates: string[]` (ISO dates the creator is already booked).
- `Service`: one bookable package (platform, price, bullets) with an optional `limit: { used, max, period }` — used to render capacity bars and disable fully-booked packages.
- `getCreator(username)` — lookup used by the profile route.
- `categories`, `reviews`, `campaigns` — supporting mock lists (reviews are shown globally on every profile, not per-creator; campaigns back a not-yet-built dashboard).
- Only 5 creators exist, each in a distinct category — any "same category" filter needs a fallback (see the "More creators to explore" logic in `creator.$username.tsx`).

## Creator profile & booking flow (`creator.$username.tsx`)

The most complex page; worth knowing the shape before touching it:

- **Packages**: an `Accordion` (not tabs) — one item per platform, expands to that platform's `ServiceOption` cards. Each card shows a capacity bar from `Service.limit` and disables itself when full (`isFull()`); the first non-full service is auto-selected (`firstAvailableId()`).
- **Negotiate a package**: a `mode: "package" | "negotiate"` state toggle that swaps the sidebar's total/CTA and the booking `Dialog`'s content between a fixed-price summary and a free-form budget+message form.
- **Availability**: the shadcn `Calendar` (react-day-picker) disables past dates and `creator.unavailableDates`; the selected date flows into the booking dialog's summary.
- **Booking dialog**: local state only (`confirmed` boolean) — "sending" a request or proposal is simulated, there's no network call.
- Similar-creators rail falls back to "other creators" when no category match exists (see data model note above).

`CreatorCard` (grid card on home/discover/matches): the photo itself is the link to `/creator/:username`; there is intentionally no separate "View Profile" button.

## Known gaps / things a future session should know

- No backend: booking, negotiation, auth, and payment are all UI-only simulations.
- `/dashboard`, `/studio`, `/auth` routes don't exist — several nav links and CTAs point at them already.
- Root `About.md` is empty; don't rely on it for product context.
- Several original Lovable-generated route files (`index.tsx`, `matches.tsx`, `discover.tsx`, `copilot.tsx`) aren't fully prettier-formatted — pre-existing, unrelated to any specific change; don't run a blanket `eslint --fix` across the repo.
